# Дизайн «Календаря звонков»

Согласованные решения по продукту (итог сессий гриллинга). Первичный контракт внешнего поведения — задание курса (`docs/design/course-requirements.md`); при конфликте оно выигрывает. Язык домена — в `GLOSSARY.md`.

## Роли и скоуп

- Один **владелец календаря**, без авторизации и личных кабинетов; гости записываются к нему.
- Рабочие часы зашиты в код, без UI-настроек.
- Экраны: главная → каталог типов события → выбор даты и слота → форма (имя, email) → экран успеха → панель «Предстоящие события» («Админка»).
- Типы события — **данные, не зашитые тексты**: владелец календаря создаёт их в админке (id, название, описание, длительность в минутах). Правка и удаление типов — вне скоупа (задание курса: только создание).
- При первом запуске seed даёт два типа события из макетов: **«Встреча 15 минут»** (id `15-min`, описание «Короткий созвон на 15 минут», 15 минут) и **«Встреча 30 минут»** (id `30-min`, описание «Созвон на 30 минут, когда 15 мало», 30 минут). «Встреча» — только имя пресета, не канонический термин.

## Доступность

- Пн–Пт, 10:00–19:00; суббота и воскресенье заблокированы.
- Невидимая сетка — **15-минутные слоты**; тип события длительностью D минут занимает ⌈D/15⌉ соседних слотов.
- Стартовые времена — каждые 15 минут, если весь интервал свободен и влезает в рабочие часы до конца дня.
- Горизонт записи — 14 дней, начиная с текущей даты (задание курса).
- Минимальное упреждение — 1 час (слоты ближе часа от текущего момента не предлагаются).
- Пересечения с существующими записями строго запрещены.

## Данные

- Хранение — `localStorage`, бэкенда нет.
- Единый модуль `src/lib/bookings.ts` (загрузка/сохранение записей, генерация слотов, проверка конфликтов) + тонкий React-хук поверх; UI-компоненты не трогают `localStorage` напрямую.
- Демо-seed при первом запуске (пустой `localStorage`): два типа события (см. «Роли и скоуп») + **три записи «Demo User»** (email `demo@example.com`), относительно текущей даты, чтобы демо не протухало:
  - «Встреча 15 минут» — первый следующий рабочий день, 11:00–11:15;
  - «Встреча 30 минут» — тот же день, 15:00–15:30;
  - «Встреча 15 минут» — второй следующий рабочий день, 10:30–10:45.

  «Следующий рабочий день» — ближайший Пн–Пт вперёд от текущей даты. Seed пишет записи напрямую: минимальное упреждение 1 час — правило предложения слотов гостю, на seed не действует. Далее это обычные записи: их можно отменить, слоты под ними заняты.
- Отмена из панели: полное удаление записи с Mantine-модалкой подтверждения; слот мгновенно освобождается.

## Маршруты (`react-router-dom`)

- `/` — главная (текущий лендинг, кнопки ведут дальше).
- `/events` — каталог типов события.
- `/book/:slug` — выбор даты и слота для конкретного типа; `:slug` = id типа события.
- `/book/:slug/confirm?slot=…` — форма (имя, email).
- `/success/:id` — экран успеха.
- `/admin` — «Предстоящие события» (панель).
- Общий хедер: на витрине — кнопка «Админка» (→ `/admin`), в панели — «Назад к витрине».

## Поток записи

- Хедер — общий на всех экранах витрины (название → `/`, справа «Админка»); на панели — «Назад к витрине».
- Контекстная навигация «назад»: «← Типы события» на `/book/:slug` (→ `/events`), «← Выбор слота» на confirm (→ `/book/:slug`).
- Календарь при входе на `/book/:slug`: текущий месяц, выбран **первый день со свободными слотами** — обычно сегодня; если сегодня выходной, рабочий день кончился или всё занято — ближайший день вперёд со слотами; если свободных дней во всём окне нет — сегодня + «Нет слотов на этот день».
- Границы календаря: выходные и дни вне 14-дневного окна **заблокированы**; навигация по месяцам не уходит дальше месяца с последним днём окна.
- Неизвестный `:slug` — молчаливый редирект на `/events`; confirm с невалидным, занятым или прошедшим `slot` — редирект на `/book/:slug`. Отдельных экранов ошибок нет.
- «Записаться ещё» (экран успеха) → `/events`.

## Форма и тексты UI

- Каталог `/events`: h1 «Типы события»; карточка — название, описание, длительность, кнопка «Записаться» (карточка целиком кликабельна, обе ведут на `/book/:id`); порядок карточек — по возрастанию длительности.
- Админка — «Создать тип события»: поля id (латиница, цифры, дефис; уникальный), название, описание, длительность в минутах.
- Форма: только Имя (обязательное, непустое) и Email (обязательный, проверка формата), валидация через `@mantine/form`.
- Экран успеха: сводка записи (тип события, дата, время, имя, email) + кнопка **«Записаться ещё»** (→ `/events`).
- Пустой день на витрине: «Нет слотов на этот день» (левая колонка) и «Выберите дату в календаре» (правая колонка, вместо списка слотов).
- Пустая панель: «Нет предстоящих записей».
- Панель «Предстоящие события»: строка записи — название типа события, интервал («21 октября, 11:00–11:15»), имя гостя, email, кнопка «Отменить»; порядок — по возрастанию начала (ближайшая сверху), один плоский список всех типов события.
- Граница «предстоящего»: показываются записи, чей конец позже текущего момента (идущая сейчас — видна); прошедшие скрыты, из `localStorage` автоматически не удаляются.
- Модалка отмены: заголовок «Отменить запись?», текст «Слот сразу освободится. Действие необратимо.», кнопки «Отменить запись» / «Оставить».
- Русская локализация дат, человекочитаемый формат macOS-стиля («21 октября, 10:00»).
- Часовой пояс не учитывается: всё в локальном времени браузера.

## Решение по ADR

- ADR-0001 (`docs/adr/0001-spa-no-backend-local-storage.md`): SPA без бэкенда — хранение `localStorage`, маршрутизация `react-router-dom`.
- 15-минутный квант сетки — не ADR: легко обратим, изолирован в генерации слотов (`src/lib/bookings.ts`).
